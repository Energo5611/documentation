# Инструкции Codex — только проект KUPIKA

## Перед работой

Прочитай README.md, docs/TECHNICAL_SPEC.md, docs/DESIGN_SYSTEM.md, docs/ACCEPTANCE.md и references/README.md. Не ограничивайся этим кратким файлом. В исходном репозитории инструкция действует только внутри KUPIKA. При переносе в отдельный репозиторий размести её в корне проекта. Не меняй глобальные инструкции пользователя.

## Неизменяемые условия

1. Создаём мобильную PWA для общих семейных покупок, НЕ интернет-магазин.
2. Никаких цен, валютных полей, итоговых сумм, скидок, оплаты, оформления заказа и доставки. Количество, масса, объём и жирность допустимы. Пользовательскую заметку не превращать в финансовую сущность.
3. Любой взрослый может покупать и составлять список. Муж/жена — не роли доступа.
4. Роль ребёнка проверяется сервером. Выбор взрослой темы не повышает права; аватар не является авторизацией.
5. Один неизменный логотип во всех темах: французский магазинчик с маркизой, три мягкие формы, утверждённая надпись. Не заменять на тележку, дом, эмодзи или другое начертание.
6. Три действительно разных оформления: «Север», «Пудра», «Солнечная». Женская тема спокойная пудровая, не ярко-розовая. Детская не копирует мужскую.
7. Стеклянные поверхности и парящие карточки не должны ухудшать читаемость и скорость.
8. Тап по карточке в режиме покупки меняет статус и запускает общий фоновый перелив в цвет продукта. Один ореол вокруг карточки недостаточен.
9. «Люблю! Целую.» не архивирует и не блокирует список. После отправки его можно дополнять.
10. Надиктовка списка и голосовое сообщение — разные действия с разными результатами.
11. Нельзя выдавать localStorage/BroadcastChannel-демо за многопользовательскую синхронизацию. Боевой источник истины — серверная база.
12. Нельзя обещать мгновенную доставку push или фоновую работу закрытой PWA во всех браузерах.

## Работа

Сначала инвентаризация существующих файлов и зависимостей, затем краткий план этапа и выполнение. Не перезаписывай чужую работу. Не устанавливай новый стек поверх уже существующего без объяснения. Веди docs/DECISIONS.md и docs/IMPLEMENTATION_STATUS.md.

Разрабатывай в согласованной рабочей папке. Код и артефакты пользователя сохраняй в «Мои проекты» после проверки пути. При недоступном диске останови файловые изменения и сообщи точную проблему.

Не покупать подписки, не использовать платный API и не публиковать приложение без отдельного согласия. Доступ к необходимому внешнему сервису запрашивать только когда без него нельзя продолжить соответствующий этап. Остальные задачи не блокировать.

## Качество

TypeScript strict; серверная проверка входных данных; проверки членства семьи и полномочий для HTTP, realtime и файлов; явные типы событий. Никаких секретов в клиенте, Git или логах. Используй реальные обработчики ошибок и доступные подписи, не пустые кнопки.

Создай команды install/dev/build/lint/typecheck/test/test:e2e и документируй их. Не утверждай, что команды уже существуют в исходном пакете ТЗ.

После этапа выполняй доступные проверки, сохраняй результаты. Для визуальных изменений делай скриншоты минимум 375, 390 и 430 CSS px во всех темах. Проверяй реальные iOS Safari/PWA и Android Chrome/PWA; эмуляция WebKit не заменяет устройство для проверки push и микрофона.

Отчёт: изменённые файлы; выполненные тесты и результат; что не проверено; реальные блокеры; следующий конкретный этап. Не называть незапущенную проверку успешной. Не считать весь проект готовым по окончании красивого прототипа.
