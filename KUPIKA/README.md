# Купика / KUPIKA — полное задание для Codex

**Версия пакета 1.2 • 10.10.2026.** Мобильное веб-приложение для разных независимых семей. Это требования и материалы для разработки, НЕ готовое приложение.

## Начать здесь

Прочитать [AGENTS.md](AGENTS.md), выполнить [START_CODEX.md](START_CODEX.md). Полное ТЗ состоит из базового документа и обязательных дополнений:

1. [TECHNICAL_SPEC.md](docs/TECHNICAL_SPEC.md) — функции, экраны, модель данных, API, синхронизация, безопасность и этапы. Базовая редакция 1.1.
2. [VOICE_ASSISTANT_3D.md](docs/VOICE_ASSISTANT_3D.md) — НОВОЕ обязательное дополнение 1.2: ассистент понимает просьбу, выбирает товар и подходящую 3D-модель/визуальный вариант; предпросмотр, уточнения и работа с реестром.
3. [PHONE_AND_FAMILIES.md](docs/PHONE_AND_FAMILIES.md) — вход по +7, приглашения по номеру, принятие получателем, независимые семьи.
4. [DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md) и [FLOATING_EFFECT.md](docs/FLOATING_EFFECT.md) — три темы, стекло, послойный логотип, парение.
5. [ACCEPTANCE.md](docs/ACCEPTANCE.md) и раздел 13 голосового дополнения — проверяемые критерии приёмки.

Новые требования 1.2 уточняют разделы 7–10/14/18 и этапы базового ТЗ. При расхождении по подбору товаров/ассетов приоритет у VOICE_ASSISTANT_3D.md.

## Обязательные решения владельца

Приложение для разных семей. Первый вход: фиксированный +7 и 10 цифр; приглашение по номеру и обязательное принятие. Номер — идентификатор, не безопасный секрет; способ подтверждения для public release, поставщик и расходы ещё согласуются. Email-вход из раннего черновика отменён.

Любой взрослый составляет список и покупает. Дети имеют отдельные разрешения. Большие объёмные карточки, текст, голосовой ассистент с автоматическим подбором 3D-товаров, отдельные аудиосообщения, уведомления, серверная синхронизация. Никаких цен, сумм, скидок, оплаты и доставки.

Один логотип для всех: маленький французский магазинчик впереди, три листочка позади на разных уровнях, отдельные мягкие тени и парение. Три отличимые темы: мужская, женская пудровая и детская. При покупке общий фон меняется в оттенок выбранного продукта. «Люблю! Целую.» отправляет, но НЕ закрывает список.

Подбор модели не равен её генерации при каждом запросе. Нужен реестр подготовленных ассетов. В сетке — лёгкие рендеры, настоящие GLB и исходники для базового набора подготавливаются отдельно. Ассистент не выдумывает отсутствующий файл, марку и упаковку. Неизвестный товар сохраняется с честным нейтральным изображением.

## Файлы

`design/tokens.json` — стартовые значения тем/движения; `data/products.seed.json` — демонстрационные товары без цен, НЕ окончательный семантический словарь; `data/voice-cases.json` — разбор количества; `data/phone-cases.json` — нормализация/безопасность входа; `data/assistant-visual-cases.json` — подбор товара и модели; `data/asset-registry.example.json` — план структуры ассетов, НЕ готовые модели.

`docs/SOURCES.md` и источники в голосовом дополнении — технические первоисточники. `.env.example` — только имена настроек, без секретов. `references/README.md` — правила использования исходных изображений.

PNG-постеры передаются отдельным архивом из переписки. В GitHub сейчас текстовое ТЗ, параметры и тест-кейсы; готовых SVG/раздельных слоёв/GLB и кода приложения ещё нет. На исходных постерах могут быть цены и старые элементы — НЕ переносить их в продукт.

## Приоритет и работа

Последние явные требования → базовое ТЗ с обязательными дополнениями → параметры → PNG-референсы → ранние концепции. Старые широкие синонимы «батон=любой хлеб», «молочка=молоко» не применять: уточнение 1.2 требует различать типы.

Ветка `codex/kupika-spec-v1`, каталог `KUPIKA`. Основную ветку и соседние проекты не менять. Локальный проект — внутри согласованной папки «Мои проекты», после проверки пути. Перед публичным запуском согласовать сервер/домен, подтверждение номера, ресурсы распознавания, политику данных и финальные ассеты. Этот пакет не отправляет SMS, не генерирует 3D и не запускает приложение.
