# Купика / KUPIKA — пакет для Codex

Версия 1.0 • 10 октября 2026 года

Это техническое задание на разработку семейного мобильного веб-приложения. **Приложение ещё не реализовано этим пакетом.** Здесь находятся требования, инструкции агенту, дизайн-токены, примеры данных и сценарии приёмки.

## Начать здесь

1. Прочитать [AGENTS.md](AGENTS.md).
2. Передать агенту [START_CODEX.md](START_CODEX.md).
3. Реализовывать по [полному ТЗ](docs/TECHNICAL_SPEC.md), [дизайн-системе](docs/DESIGN_SYSTEM.md) и [критериям приёмки](docs/ACCEPTANCE.md).

## Главные решения

- Один общий семейный список; любой взрослый может составлять его, дополнять и покупать.
- Большие карточки продуктов с объёмными изображениями. **Без цен, сумм, скидок, оплаты и доставки.**
- Отметка покупки нажатием на карточку; изменения видны остальным участникам.
- При покупке общий фон мягко приобретает оттенок продукта, а не только подсвечивается карточка.
- Три различимые темы: мужская «Север», женская «Пудра», детская «Солнечная». Тема не определяет права.
- Единый логотип: маленький французский магазинчик с полосатой маркизой и тремя мягкими формами за ним. Цвета и пропорции логотипа не меняются между темами.
- Два разных голосовых действия: надиктовать список и отправить аудиосообщение.
- Кнопка «Люблю! Целую.» отправляет список/тёплое сообщение, но не закрывает список.
- Детские профили добавляют родители; публичных профилей и общения с незнакомыми нет.

|---|---|
| `docs/TECHNICAL_SPEC.md` | Функции, экраны, роли, API, данные, синхронизация, безопасность, этапы |
| `docs/DESIGN_SYSTEM.md` | Бренд, темы, стекло, карточки, динамический фон, тексты |
| `docs/ACCEPTANCE.md` | Проверяемые сценарии и критерии готовности |

| `design/tokens.json` | Стартовые числовые параметры дизайн-системы |
| `data/products.seed.json` | Образцы продуктов без цен; цвет реакции для каждого |
| `data/voice-cases.json` | Проверки разбора русских списков |
| `references/README.md` | Приоритеты визуальных референсов и обязательные исправления |
| `.env.example` | Перечень настроек, не реальные секреты |

PNG-референсы предоставляются в сопутствующем ZIP-пакете. В этом GitHub-коммите находятся текстовые инструкции и данные; не выдавать отсутствие PNG в репозитории за наличие готовых SVG/3D-ассетов. При работе только с GitHub запросить ZIP у владельца до финальной визуальной приёмки. Параллельно можно реализовывать логику и компоненты по текстовой дизайн-системе.

## Приоритет требований

Последние явные замечания владельца → это ТЗ и дизайн-система → параметры в JSON → изображения-референсы → старые концепции. Новые договорённости фиксировать через обновление ТЗ и журнал решений.

В референсах встречаются цены, неверные даты, неодинаковые логотипы, магазинные кнопки и случайные подписи шрифтов. Это не разрешение повторять ошибки. Содержимое постеров не является готовой моделью данных или спецификацией интерфейса.

## Размещение

Материалы опубликованы в отдельной ветке `codex/kupika-spec-v1`, каталог `KUPIKA`. Существующие проекты репозитория не менять. Для локальной разработки использовать согласованную папку проекта внутри «Мои проекты», проверив реальное расположение и доступность диска. Не создавать новый проект в произвольной папке и не пытаться восстановить сетевое хранилище разрушительными командами.

## Что ещё требует согласования перед запуском

Домен, сервер, доступ к почтовому сервису для входа, фактические ресурсы для распознавания речи, финальные исходники логотипа. До согласования не покупать сервисы, не подключать платные API и не выкладывать реальные семейные данные. Остальные предложенные настройки описаны в ТЗ и позволяют начать прототип без дополнительных вопросов.
