# Проверки приёмки — Купика

Версия 1.1 • 10.10.2026. Изначально все пункты NOT RUN. Это план, не результаты выполненного тестирования приложения.

Стенд: два взрослых A/B и ребёнок C одной тестовой семьи, взрослый D другой семьи; независимые сессии. iPhone Safari/PWA, Android Chrome/PWA и desktop. Эмуляция не заменяет физическое устройство для микрофона, установки и push. Только вымышленные/разрешённые тестовые данные.

## A. Вход, телефон и приглашения

- [ ] A01. +7 фиксирован, остальные 10 цифр вводятся удобно; маска/вставка/нормализация проходят phone-cases.json. Неверные номера не обрезаются молча.
- [ ] A02. Один лишь введённый телефон не выдаёт сессию существующего пользователя и не открывает его семью.
- [ ] A03. Реально проверенный код проходит, неправильный/истёкший/использованный не проходит. Попытки, повторная отправка и дневные лимиты действуют.
- [ ] A04. Mock AuthProvider невозможен в production; SMS и коды не публикуются/не логируются. Тестовые номера не отправляются реальному провайдеру.
- [ ] A05. Существующая сессия позволяет обычный повторный вход без нового ввода номера; выход/отзыв действительно её закрывает.
- [ ] A06. Нет выдачи имени/аватара/семей по произвольному номеру до разрешённого контекста. Ответы входа не перечисляют пользователей.
- [ ] A07. Приглашение по телефону создаёт pending, не membership. До принятия список, аудио, дети и телефоны семьи недоступны.
- [ ] A08. Принять может только авторизованный адресат с подтверждённым приглашённым номером. Пересланная ссылка у D не даёт доступ.
- [ ] A09. GET ссылки не присоединяет. «Принять» атомарно создаёт одно членство, два повтора не создают дубль.
- [ ] A10. «Отклонить», отзыв, истечение, блокировка повторного отправителя и лимиты работают. Отправитель не видит чужие приватные данные.
- [ ] A11. Новый пользователь после регистрации получает своё ожидающее приглашение, без автоматической лишней семьи. Пользователю без приложения не обещают push.
- [ ] A12. Смена номера сохраняет userId, не объединяет разные аккаунты; восстановление доступа и риск повторной выдачи номера рассмотрены до public release.

## B. Семейные права

- [ ] B01. A/B могут составлять, дополнять и покупать одинаково. Тема/пол не определяют права.
- [ ] B02. Прямой API, realtime, event replay и URL медиа семьи A/B недоступны D.
- [ ] B03. Детская роль C задаётся приглашением взрослого; смена темы, аватара и client payload не повышает права.
- [ ] B04. Пожелание ребёнка ждёт согласования и не считается необходимым/купленным раньше одобрения.
- [ ] B05. Разрешение C покупать действует только для выбранного списка; отзыв проверяется сервером.
- [ ] B06. Нельзя удалить последнего владельца без передачи. Отозванные участники теряют активные соединения и новые файлы.
- [ ] B07. Переключение семей не смешивает кэш, подписки и исходящую очередь. Каждая операция остаётся в исходной семье.

## C. Списки и карточки

- [ ] C01. Черновик видит только автор; публикация «Люблю! Целую.» делает его общим один раз и не архивирует.
- [ ] C02. После отправки новые товары добавляются на ходу, у второго клиента появляются без reload/потери прокрутки.
- [ ] C03. «Я в магазин» не блокирует второму взрослому покупки; «Я дома» завершает поход, не закрывает список.
- [ ] C04. Тап большой зоны отмечает покупку и сообщает автора/статус B. Меню/количество/голос не вызывают случайный toggle.
- [ ] C05. Отмена синхронизируется, счётчик верен, товар не исчезает мгновенно из-под пальца.
- [ ] C06. «Нет в магазине» не равно куплено. Вопрос/замена связаны с правильной карточкой.
- [ ] C07. Изменение количества уже купленного не создаёт незаметно новое выполненное требование.
- [ ] C08. Несовместимые единицы и разные виды молока не объединяются молча.
- [ ] C09. Всё куплено не означает автоархив. Копия истории имеет новые ID и needed, не портит исходник.
- [ ] C10. Цен/валют/скидок/сумм/оплаты нет в системном UI, модели и seed. Количество/жирность есть; свободные заметки не уничтожаются фильтром цифр.

## D. Фон и объём

- [ ] D01. Покупка меняет общий корневой фон под сеткой/шапкой/навигацией, не только ореол карточки.
- [ ] D02. Молоко/хлеб/сыр/зелень/яблоки дают ожидаемый мягкий оттенок; логотип, фото и текст не перекрашиваются.
- [ ] D03. Переход 450–700 мс без белых вспышек. 15 быстрых тапов не создают очередь анимаций/рост DOM; последняя цель побеждает.
- [ ] D04. Отмена последней возвращает предыдущий действующий оттенок, иначе базу; отмена старой не сбрасывает новую.
- [ ] D05. Серверный отказ откатывает статус и фон; ack не повторяет эффект. Нет картинки — цвет категории без задержки покупки.
- [ ] D06. Удалённая покупка по выбранному правилу не перекрашивает экран составителя. Reduced motion/отключение фона соблюдаются.
- [ ] D07. Лавка и три листочка имеют РАЗНЫЕ уровни и индивидуальные согласованные тени; глубина видна в покое.
- [ ] D08. Магазин впереди; листочки позади не на одной плоскости. Есть настоящие раздельные ассеты и статический экспорт, не PNG, объявленный layered-сценой.
- [ ] D09. Параллакс деликатный, не мешает касанию/прокрутке, выключается при reduced motion. Системная иконка не обещает CSS-анимацию.
- [ ] D10. Единый логотип во всех темах. Женская пудровая, детская не копия мужской. Сравнение одинаковых четырёх продуктов.

## E. Голос

- [ ] E01. «Надиктовать список» и «Голосовое» различимы и не подменяют друг друга.
- [ ] E02. Реальная запись воспроизводится iPhone→Android и обратно. Play/pause/длительность верны, автопроигрывания нет.
- [ ] E03. Отмена/закрытие освобождает микрофон. Отказ доступа, звонок, блокировка и лимит размера не теряют список.
- [ ] E04. Надиктовка русского текста даёт редактируемый предпросмотр; тишина не создаёт выдуманные товары.
- [ ] E05. voice-cases.json проходит: количество, десятичные, жирность, неизвестные слова/неоднозначности.
- [ ] E06. Недоступный STT имеет честную ошибку, повтор и ручной ввод. Оригинал надиктовки не отправляется семье без отдельного действия.
- [ ] E07. Двойная отправка/повтор upload после сети не создают два сообщения; незавершённое аудио не выдаётся за отправленное.

## F. Синхронизация и офлайн

- [ ] F01. Проверка на независимых сессиях и серверной БД, не BroadcastChannel-имитация. Reload/перезапуск сервера не теряет подтверждённые данные.
- [ ] F02. Тройная отправка operationId создаёт одно изменение; то же ID с другим телом — конфликт.
- [ ] F03. Одновременная одинаковая покупка A/B сходится без дубля события. Несовместимые правки версии дают 409 и разрешение, не тихую потерю.
- [ ] F04. Разрыв соединения, пропущенные события, replay/snapshot и возврат сети не создают пропусков/двойных покупок.
- [ ] F05. Офлайн изменения явно pending; публикация→товары→сообщение сохраняют зависимости. Tombstone не даёт воскресить удалённый товар.
- [ ] F06. Выход/смена аккаунта очищает частное; очередь старого пользователя не отправляется под новым. Service worker update не теряет очередь.
- [ ] F07. При выбранной нормальной сети измерены локальный отклик до 100 мс и p95 изменения второго открытого клиента до 2 с; условия измерения указаны.

- [ ] G03. Проверена доставка в доступном сценарии устройства, без обещаний гарантированного времени. Старый push открывает актуальные данные.
- [ ] G04. Группировка событий, отсутствие собственного push, тихие часы, несколько устройств, невалидные подписки, повторы работают.
- [ ] G05. Нет обещания постоянного WebSocket/записи при закрытой PWA; Background Sync не единственный путь.
- [ ] G06. 320/375/390/430 CSS px, desktop, 200% текста, safe-area/клавиатура: нет переполнения и перекрытых действий.
- [ ] G07. Screen reader/клавиатура/focus/закрытие панелей/нецветовые статусы проверены. Контраст всех тем/фонов и зоны нажатия измерены.

- [ ] G09. Нет секретов, настоящих телефонов, детских аудио и семейных списков в Git, frontend bundle, логах и внешней аналитике.

Формат отчёта: `ID | среда/версия | шаги | ожидание | факт | pass/fail/not-run | доказательство`. Скриншоты/видео/логи не должны содержать реальные приватные данные. Дополнительные визуальные проверки — FLOATING_EFFECT.md.
